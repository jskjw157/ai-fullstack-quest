## 1. 제품 한 줄 정의

**AI 풀스택 개발자가 되기 위해 공부하고, 퀴즈를 풀고, 실제 기능을 구현하면 캐릭터가 성장하는 개인용 학습 RPG.**

게임의 성장은 학습 활동을 지속하도록 돕는 표현이다. 경험치나 레벨을 실제 업무 역량의 객관적인 인증처럼 표시하지 않는다.

## 2. 배경과 해결할 문제

사용자는 연봉을 높이는 이직과 AI 에이전트를 활용하는 풀스택 개발자로의 성장을 원한다. Java/Kotlin·Spring 백엔드 경험이 있으므로 모든 영역을 입문부터 반복하는 학습 서비스는 적합하지 않다.

현재 해결하려는 문제는 다음과 같다.

- 공부할 주제가 넓어 오늘 무엇을 해야 할지 결정하기 어렵다.
- 읽고 이해한 것과 혼자 설명하거나 구현할 수 있는 것을 구분하기 어렵다.
- AI로 코드를 빠르게 만들어도 본인이 배운 내용이 남지 않을 수 있다.
- 학습 기록·오답·실제 구현 결과가 분리돼 성장을 돌아보기 어렵다.

**핵심 원칙: 완료한 강의 수보다 설명·응용·구현의 증거를 남긴다.**

## 3. 확정된 사항과 제안 사항

### 사용자와 합의한 사항

- 첫 사용자는 본인 한 명이다.
- 최종 성장 방향은 AI 풀스택 개발자다.
- 학습과 퀴즈 수행에 따라 캐릭터 능력치가 오른다.
- 기존 VPS의 T3 Code를 개발 작업공간으로 사용한다.
- GitHub 저장소는 공개로 만든다. **저장소 공개와 개인 학습 데이터·서비스 공개는 별개다.**
- **현재 개발 역할:** 제품·기술 설계는 Puck, UI·UX는 AGY의 Gemini 3.8 Flash high, 구현은 T3 native Codex의 6.1 Sol high, 독립 검토·리뷰는 T3 native OpenCode의 DeepSeek 4.1 Flash max로 진행한다. OMO는 제외한다. 이는 사용자가 승인한 목표 구성으로, 각 모델 ID·추론 설정·인증·실행 성공 여부는 실제 T3에서 확인한 뒤 별도로 보고한다. 최초 Amp low/medium 분담은 대체됐다. 실제 설정·검증 결과와 T3 사용법은 [역할·모델 설정](./roles.md)에 기록한다.

### 이 PRD의 제안 기본값

- 모바일과 데스크톱에서 사용하는 반응형 웹앱으로 시작한다.
- 첫 버전은 캐릭터 한 명, 다섯 능력치, 하나의 학습 경로만 지원한다.
- 실시간 AI 문제 생성보다 고정된 초기 콘텐츠와 검증 가능한 채점을 우선한다.
- 코딩 미션은 설명·코드 링크·테스트 결과를 기록한다. 서버가 임의의 제출 코드를 실행하지 않는다.
- 제품 내 AI 코치와 콘텐츠 개인화는 기본 학습 흐름이 완성된 뒤 추가한다.
- 아래 경험치 값과 성공 지표는 실사용 후 조정하는 초안이며 사용자 확정값이 아니다.

## 4. 목표와 비목표

### 목표

1. 앱을 열면 다음에 할 학습·복습 활동을 바로 알 수 있다.
2. 학습 → 퀴즈 → 피드백 → 성장 → 복습이 하나의 흐름으로 이어진다.
3. 단순 활동량과 개념 숙련도를 구분해서 보여준다.
4. 실제 개발 미션에 결과물과 본인의 설명을 남긴다.
5. 공개 코드로 풀스택 개발·AI 활용·검증 과정을 설명할 수 있다.

### MVP에서 하지 않을 것

- 다중 사용자, 소셜 로그인, 랭킹, 결제, 팀 기능
- 전투·상점·장비·가챠·복잡한 애니메이션
- 자체 모델 학습, 로컬 대형 모델 상시 구동
- 임의 코드 실행 샌드박스와 자동 GitHub 감시
- 정답 검증 없는 AI 자동 채점에 기반한 숙련 인증
- 이번 게임이 완성될 때까지 이직 지원을 중단하는 계획

## 5. 핵심 사용자 흐름

### 처음 사용

1. 목표를 AI 풀스택 개발자로 선택한다.
2. 이미 경험한 기술과 집중할 영역을 고른다. 자기평가임을 표시한다.
3. 짧은 진단 문항으로 시작 지점을 제안받는다.
4. 캐릭터와 첫 미션을 확인한다.

경력이나 자기평가만으로 숙련 상태를 자동 확정하지 않는다. 이미 아는 영역의 기본 학습은 건너뛰되, 진단 결과와 실제 수행 기록을 구분한다.

### 평소 사용

1. 대시보드에서 오늘의 미션과 복습 대상을 확인한다.
2. 개념 요약과 참고 자료를 읽는다.
3. 퀴즈에 답하고 정답 이유와 오답 이유를 확인한다.
4. 필요하면 작은 코딩 미션을 수행하고 결과물과 설명을 기록한다.
5. 획득 경험치와 능력치 변화를 확인한다.
6. 다음 활동을 선택하거나 종료한다.

연속 출석이 끊겨도 경험치가 사라지지 않는다. 재방문을 돕되 벌점으로 압박하지 않는다.

## 6. 성장 시스템

### 능력치

| 영역 | 학습·미션 예시 |
| --- | --- |
| 프론트엔드 | 컴포넌트, 상태 관리, 폼, 접근성, API 연동 |
| 백엔드 | API 설계, 인증, DB·SQL, 트랜잭션, 테스트 |
| AI 엔지니어링 | LLM API, 구조화 출력, 도구 호출, RAG, 평가 |
| 배포·운영 | 배포, 설정·비밀 관리, 로그, 장애 분석 |
| 설계·검증 | 요구사항 분해, 기술 선택, 코드 리뷰, 결과 검증 |

### 경험치와 숙련도의 분리

- **경험치·레벨:** 수행한 학습 활동의 누적 기록.
- **개념 상태:** 미학습 → 학습 중 → 확인됨 → 복습 필요.
- **미션 증거:** 답안, 코드 링크, 테스트 결과, 회고.
- AI 피드백, 객관식 채점, 본인 완료 확인을 서로 다른 검증 방식으로 표시한다.

### 경험치 기본안

| 활동 | 경험치 제안 | 중복 방지 |
| --- | --- | --- |
| 개념 학습 완료 | 5 | 개념별 최초 1회 |
| 퀴즈 정답 | 10 | 문항 버전별 최초 정답 1회 |
| 코딩 미션 완료 | 30 | 결과물·설명 기록 필수, 자기 확인임을 명시 |
| 예정된 복습 통과 | 5 | 동일 복습 회차 1회 |

오답 후 재도전은 허용하지만 같은 문항을 반복해서 경험치를 무한 획득할 수 없다. 서버는 경험치 지급을 멱등적으로 처리한다. 레벨 곡선과 세부 수치는 코드에 흩어 쓰지 않고 설정으로 관리한다.

### 초기 복습 규칙

오답 문항은 다시 학습할 목록에 넣는다. 통과한 개념은 기본적으로 1일·3일·7일 뒤 재확인하도록 제안한다. 날짜 경계는 Asia/Seoul 기준이며 동일 회차가 중복 생성되지 않게 한다. 복잡한 적응형 알고리즘은 후속 범위다.

### 초기 콘텐츠 범위

첫 학습 경로는 **‘AI 기능이 있는 작은 웹서비스를 끝까지 만들기’**로 한다. 이 게임 자체의 개발 경험을 미션으로 연결할 수 있다.

- 화면과 API 연결
- 데이터 저장·검증
- LLM 호출과 출력 검증
- 오류·타임아웃 처리
- 테스트·리뷰
- 배포·로그 확인

시드 콘텐츠는 완성도 있는 소수부터 시작한다. 제안 최소량은 개념 6개, 고정 퀴즈 12개, 코딩 미션 3개다. 퀴즈와 해설은 사람이 검토하고, 변동 가능한 기술 정보에는 공식 출처를 남긴다.

## 8. UI·UX 요구사항

### 필요한 화면

1. 시작·목표 설정
2. 대시보드와 캐릭터
3. 학습 경로
4. 개념·미션 상세
5. 퀴즈와 결과 피드백
6. 성장·복습 기록
7. 설정·데이터 내보내기

### 디자인 방향

**학습 도구의 가독성을 중심에 두고, 캐릭터와 성장 연출로 RPG 감각을 더한다.** 장식이 문제 읽기·코드 확인·다음 행동을 방해하지 않아야 한다.

- 핵심 행동은 화면마다 명확하게 하나를 우선한다.
- 색상만으로 정답·오답·잠금 상태를 구분하지 않는다.
- 키보드 조작, 포커스, 충분한 대비, 동작 줄이기를 지원한다.
- 360px 수준의 좁은 화면과 데스크톱에서 핵심 흐름이 깨지지 않는다.
- 로딩·빈 목록·통신 실패·중복 클릭·저장 실패 상태를 디자인에 포함한다.
- 성장 연출 후 무엇을 배웠고 다음에 무엇을 할지 보여준다.

AGY의 산출물은 이미지 한 장이 아니라 화면 흐름, 컴포넌트·디자인 토큰, 상태별 동작 명세여야 한다.

## 9. 제품 내 AI 코치 — 후속 기능

개발 과정에서 쓰는 AGY·Amp와 **사용자에게 제공하는 앱 내부 AI 기능은 별개**다. MVP는 제품용 AI 키 없이도 핵심 학습 흐름을 사용할 수 있어야 한다.

후속 AI 코치는 다음을 지원한다.

- 정답을 바로 주기보다 단계별 힌트 제공
- 오답 원인과 관련 개념 설명
- 미션 결과에 대한 설명·회고 질문
- 약한 개념을 반영한 다음 활동 제안

AI 생성 문제는 검토 대기 상태로 저장하고 바로 검증된 문제처럼 취급하지 않는다. AI 평가는 보조 피드백으로 표시하며 공식 정답이나 실제 테스트 결과보다 우선하지 않는다. 개인 코드·답안을 외부 모델에 전송하는 경우 전송 범위를 알 수 있어야 한다.

호출은 서버에서 수행하고 API 키를 브라우저에 노출하지 않는다. 타임아웃·재시도 상한·사용량 기록·비용 제한을 둔다. 제공자·모델·예산은 도입 시 별도로 결정한다. 개발용 구독을 제품 API로 사용할 수 있다고 가정하지 않는다.

## 10. 데이터와 기술 구조

### 주요 데이터

프로필, 능력 영역, 학습 노드, 콘텐츠·문항 버전, 퀴즈 시도, 미션 제출, 경험치 이벤트, 복습 회차를 저장한다.

경험치 이벤트는 활동·회차를 식별하는 고유 키를 갖는다. 문항 변경 이후에도 과거 답안과 당시 해설을 재구성할 수 있게 한다. 개인 답안·일지·백업은 공개 저장소와 분리한다.

### 기술 원칙

- 첫 버전은 단일 사용자·단일 서비스 배포에 맞게 작게 구성한다.
- 프론트는 React·TypeScript를 우선 검토한다.
- 백엔드는 사용자의 Spring 경험과 현재 VPS 자원, 이미 만들어진 기반을 고려해 결정한다. Spring Boot·Kotlin과 경량 TypeScript 서버 중 무엇을 택하든 이유를 ADR로 남긴다.
- 기존 구현을 확인하지 않고 스택을 갈아엎지 않는다.
- 데이터는 영속 DB에 저장하고 스키마 변경을 관리한다. DB 선택도 현재 운영 환경 확인 후 확정한다.
- 마이크로서비스, Kafka, 벡터 DB를 MVP에 필요 없이 추가하지 않는다.
- 라이브 VPS에서 대형 모델이나 무거운 빌드를 상시 돌리지 않는다.

## 12. 보안·운영 요구사항

- **GitHub public은 코드 공개다. VPS 관리자 화면·T3·Amp·학습 기록을 공개하지 않는다.**

- 저장 실패나 서버 오류가 발생해도 경험치만 반영되거나 답안만 사라지는 불일치를 방지한다.

## 17. Medium 독립 코드 리뷰 결과 — 이력, 수정 승인 대기

대상은 동일 커밋 `06f7a60`이다. **기반 구조를 유지하고 개발을 계속할 수 있지만, 실데이터를 쌓거나 XP 기능을 확장하기 전에 P1 두 건의 수정이 필요하다.** 스택 전면 교체가 필요한 증거는 발견하지 못했다.

상세: [medium 코드 리뷰와 재현 근거](https://ampcode.com/artifacts/ai-fullstack-quest-medium-06f7a60-cb347aee-918a-452c-8856-bae7da8e78ae).

### 우선 수정할 P1

1. **R1 — 요청 재전송으로 XP 중복 지급.** 동일 요청이 매번 새 활동으로 저장된다. INSERT 성공 후 응답용 조회만 실패시킨 장애 주입에서는 API가 500이어도 15 XP가 남았고, 재시도 시 30 XP가 됐다. 클라이언트가 유지하는 요청 ID·DB 고유 제약·동일 키/다른 본문 충돌 계약이 필요하다. 요청 재시도의 멱등성과 제품의 문항·회차별 보상 고유성은 별개로 설계한다.
2. **R2 — 다른 웹 출처의 로컬 데이터 쓰기.** 다른 loopback 출처의 브라우저에서 `no-cors`·`text/plain` POST로 XP 0→10을 실제 재현했다. JSON Content-Type과 승인된 Origin/CSRF 경계를 쓰기 전에 검사해야 한다. 인터넷 공격·VPS 공개 노출까지 재현한 것은 아니다.

### 후속 보완 P2

- 저장 중 새로 작성한 초안이 이전 요청의 성공 응답 뒤 지워진다.
- 서버의 서울 날짜와 브라우저 현지 시간 표기가 달라 날짜가 어긋난다.
- 선언된 Node 지원 범위와 잠긴 Vite/Vitest 의존성의 engines가 맞지 않는다. 메타데이터 대조 결과이며 Node 22.5 실행 실패를 재현한 것은 아니다.

### 확인한 것과 하지 않은 것

medium이 기존 테스트 29개와 타입 검사·빌드를 직접 재실행해 통과했다. 추가로 INSERT 실패 시 행·XP가 남지 않는 점, 서울 자정·윤일·연도 경계, 파일 DB와 실제 서버 프로세스 재시작 후 보존을 확인했다. 시험한 정적 경로에서 루트 밖 표식 누출은 없었다. 이 결과는 전체 보안 감사나 백업 복원 성공을 뜻하지 않는다.

네 개/다섯 개 능력치와 XP 제안값 차이는 미결정이지 결함으로 세지 않았다. 리뷰 과정에서 원본 코드·main·서비스·인증·개인 DB를 바꾸지 않았고 커밋·푸시·배포도 없었다. 임시 검증 서버는 정리했으며 앱은 계속 정지 상태다.

### 권장 다음 작업 — 아직 배정하지 않음

초기에는 Amp low 수정·medium 재검토를 제안했으나, 이후 사용자가 Codex/OpenCode 전환을 요청했으므로 **해당 도구 배정은 실행하지 않는다.** R1/R2 수정과 회귀 테스트 후 독립 재검토가 필요하다는 판단은 유지한다. 의도적으로 새 활동을 여러 번 기록하는 행위를 제목·날짜만으로 막지 않는다. P2는 같은 수정 단위에 넣을지 범위를 정한다. 이후 실제 퀴즈·복습 확장 전에 시도·증거·보상 이벤트, SQLite 마이그레이션·복구 계약, 표시 시간대를 확정한다.

## 18. T3 OpenCode·OMO 호환성 조사 — 이력

### 결론

**현재 VPS의 T3 native OpenCode 2.2.5에서는 OMO 플러그인 로드만 가능하며, OMO 기능 통합은 불가하다.** 설치·운영 설정 변경은 승인하지 않았으며 조사 후에도 적용하지 않았다.

### 확인한 근거

- 대상 패키지는 `oh-my-opencode@5.1.64` / `oh-my-openagent@5.1.64`, 저장소는 https://github.com/code-yeongyu/oh-my-openagent 이다. `omo-ai@5.1.64`는 별도의 standalone OmO Native 런타임이다.
- T3 0.1.5는 T3 runtime 사용자 HOME에서 OpenCode 2.2.5의 `serve` HTTP v2 API를 사용한다. ACP 방식이 아니다.
- 운영과 분리한 임시 HOME/XDG 스모크에서 `/api/plugin`의 active를 확인했지만 `/api/agent`에는 기본 에이전트만 노출됐다.
- 해당 OMO 버전의 v2 진입점은 안내 로그만 남기는 stub이며 agents/tools/hooks가 활성화되지 않는다고 명시한다. 따라서 OMO의 에이전트·하위 작업·백그라운드·모델 매핑을 사용할 수 없다.
- T3 어댑터의 실행 agent 선택도 build/plan 중심이다. 플러그인을 설치했다고 OMO 에이전트 선택 UI나 자동 작업 전달이 생기지 않는다.
- T3 runtime과 분리된 별도 터미널 OpenCode 1.18.30은 T3가 쓰는 2.2.5와 다른 실행환경이다. 1.x의 OMO 실동작·T3 연결은 이번에 검증하지 않았다.

### 선택지와 권장안

| 경로 | 확인된 범위 | 판단 |
| --- | --- | --- |
| T3 native Codex/OpenCode, OMO 제외 | 둘 다 native·enabled. Codex 0.166.0 / OpenCode 2.2.5 | T3 중심 개발의 권장 경로. 역할·모델과 자동 전달은 별도 확정·검증 |
| 별도 OmO Native terminal | T3 provider가 아닌 별도 런타임 후보 | OMO가 필수일 때 검토. 설치·인증·기능은 미검증 |
| 별도 OpenCode 1.x + OMO 서버를 T3에 연결 | 1.x 제한적 지원 및 agent 매핑 제약 | 우회 후보일 뿐 미검증. 운영 버전 다운그레이드나 대체를 권장하지 않음 |

T3 OpenCode에서 저장된 인증은 OpenCode Go만 확인했다. 다른 모델 구독이 자동으로 공유된다고 가정하지 않으며 추가 경로에는 별도 인증 확인이 필요하다. 인증 내용은 열거하거나 문서에 저장하지 않았다.

조사 당시 임시 스모크는 종료·정리했고 운영 T3/OpenCode·인증·제공자 설정·서비스를 바꾸거나 재시작하지 않았다. **이후 사용자가 OMO 없이 T3 native 경로를 선택하고 Codex 6.1 Sol high, OpenCode DeepSeek 4.1 Flash max, 기존 AGY UI·UX 분담으로 진행하도록 승인했다.** 현재 역할은 11절에 반영했으며 실제 설정·실행 검증 결과는 [역할·모델 설정](./roles.md)에 기록한다.
